# Proxynode Audit Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement bounded connection audit collection and reliable batch delivery in the new proxynode project.

**Architecture:** One bounded asynchronous collector, immutable FIFO memory/disk batches, one bounded uploader, and hooks in both Xray dispatcher entry paths. Limits are process-wide.

**Tech Stack:** Existing Go/Xray fork; standard library queue/files/HTTP and existing panel client.

**Spec:** `docs/superpowers/specs/2026-10-27-audit-design.md`

## Global Constraints

- Audit memory below 256 MiB; spool at most 1 GiB; reject newest records on saturation.
- Preserve original v2node and panel; no production access; retain upstream attribution.
- No additional database or external service.

## Review Focus

- Failed or ambiguous acknowledgment must not delete data (Task 2).
- Multiple nodes must share capacity and retain correct destination (Tasks 1, 3).
- Reload/stop must cancel uploads and preserve queued data (Tasks 1, 3).
- Original IP and sniffed domain must both survive (Task 3).
- Disk unavailable/full must not stall proxy connections or grow memory (Task 1).
