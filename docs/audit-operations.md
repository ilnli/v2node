# 审计缓存运行说明

## 容量与丢弃规则

配置位于顶层 `Audit`，对进程内所有 `Nodes` 共享生效：

| 字段 | 默认 | 范围/含义 |
| --- | --- | --- |
| `Enabled` | `false` | 是否采集并上报 |
| `Directory` | `/var/lib/proxynode/audit` | 独占、可写、持久缓存目录 |
| `MemoryMiB` | `64` | 1–128，内存中序列化批次预算 |
| `DiskMiB` | `1024` | 1–1024，磁盘预算 |

采用固定入口队列（4096 条）、最多 64 条/256 KiB 一批、最多 65536 个排队批次，以及单个上传请求。目标地址和域名各最多 253 字节，超长记录拒收。默认内存预算故意低于 256 MiB，为元数据、拷贝、编码、解码及 HTTP 缓冲留出空间；不使用全局 Go 内存限制干扰 Xray。配置最多支持 256 个审计节点。

批次正常进入内存；内存达到阈值后，新批次写入磁盘，按原队列顺序消费。磁盘积压排空后恢复内存模式。每个磁盘批次独立存成文件，完整确认后整文件删除。

磁盘计费包含文件数据向 4 KiB 取整及每文件额外 4 KiB 元数据余量；内存批次也预留同样的磁盘空间，保证正常退出时可落盘。因此实际缓存数据通常小于配置额度，且内存与磁盘容量不简单相加。使用专用目录，不放入其他文件；异常文件系统块大小或额外卷元数据不属于应用文件字节配额。

**满容量不删除旧批次。** 磁盘预算、批次数、入口队列任一达到上限，或者磁盘写入失败时，拒绝新记录/新批次并累计 `dropped_new_records`。磁盘和网络 I/O 在后台执行，不阻塞连接分发。丢弃日志最多每 30 秒汇总一次，退出时再次输出总数。早于鉴权失败或被设备限制拒绝的连接不计入审计。

## 重启、重载与故障

正常 SIGTERM/SIGINT 及配置重载会停止上报、排空入口队列、将内存批次落盘后释放文件锁。磁盘批次重启自动恢复；残留未完成的 `.batch.tmp` 文件清除。两个进程不可同时使用同一缓存目录。

内存模式不承诺强制杀进程、断电时零丢失。正在写入的临时批次也可能丢失；确认后的文件在突然断电后重现可能产生重发，面板仍须去重。

变更/删除面板地址或节点 ID 后，旧目标批次仍保留；单一 FIFO 队首若无法匹配当前配置，会等待恢复该目标配置，不会转发给其他节点。一个面板节点持续失败也会阻塞全局 FIFO 的后续上报，但代理连接继续工作。更换密钥不改变缓存目标身份。

已有磁盘缓存超过新配置额度时拒绝启动审计，不擅自删旧记录。读到损坏文件时保留文件并暂停该队列，需人工检查；若明确放弃这些数据，可停进程后将整个目录移到别处，再使用空目录启动。不要在运行中修改缓存文件。
